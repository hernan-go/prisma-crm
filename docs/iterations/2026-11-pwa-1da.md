## Implementación local

- 022 sustituye únicamente `chk_identity_audit_operation`, con DROP y ADD en un
  solo ALTER, nombre conservado y ENFORCED. Mantiene la excepción de operación NULL,
  la obligación de JSON objeto para operaciones identificadas y el UUID estándar
  en minúsculas. No cambia columnas, otros CHECK, índices ni datos.
- Preflight exclusivo de 022 en el runner: exige 021 registrada, tabla InnoDB,
  columnas esperadas, restricción presente/ENFORCED y una de las dos variantes
  conocidas. Compara estructura booleana y literales, reconociendo la representación
  de metadatos MySQL; no elimina indiscriminadamente paréntesis. Rechaza datos
  incompatibles con la condición nueva antes del DDL.
- Si el DDL termina y no se confirma el registro, el runner se detiene con mensaje
  específico, sin reintentar. Los fallos de limpieza no ocultan ese mensaje.
  No se infiere que el registro esté ausente: ante transporte ambiguo debe leerse.
- Las instalaciones con 021 ya correcta también recorren 022 y conservan el mismo
  contrato. Con 022 registrada, el runner la omite como las migraciones anteriores;
  esto no sustituye el postflight del esquema.
